# 链表式知识记忆管理（Linked-List Memory）

大型项目（多协作者/多文档/多技能/长期演进）的知识资产按**链表**组织与维护，保证知识联系不被改动打散。

## 适用场景

- **大项目启动 = 默认启用**：建库/新系统/大规模重构等工程开工即挂本技能，避免"只建库不挂链"
- **记忆容量管理**：内置记忆到达水位线（如 80%）即触发整理（压缩/外挂/重接链；实战可降 30-40 个百分点）
- 管理大型项目的记忆体系（内置记忆 / fact_store / 技能 / 文档引用）
- **改动任何"知识节点"之前**：删条目、删文件、改文档、改技能、重组目录
- 项目知识整理/重组后的完整性验收
- 新会话/新参与者需要可靠激活项目知识的场景（激活链设计）

## 核心模型

| 概念 | 定义 | 实例 |
|---|---|---|
| **节点** | 知识单元：memory 条目、fact 事实、技能、文档、文件 | memory 里"某项目数据资产"条目 |
| **指针** | 节点间的引用关系："详见 X"、"路径引用"、"引用技能"、"关联事实" | 技能里的 `<DATA_DIR>/dataset` 路径 |
| **链** | 从入口（L1 索引）到内容（L2 载体）的通路 | memory 条目 → fact → 技能 → 文档 |
| **悬空指针** | 指向已删/已移目标且未重接的引用 = 链断裂 | 技能还引用已删除的打包产物 |

## 链表五律（操作铁律）

1. **删除 = 重接链**：删除任何节点前，先找出所有指向它的指针（grep 技能库/文档/其他条目），重定向到继承者或同步删除。**禁止留下悬空指针**。
2. **修改 = 查前后指针**：改完检查入链（谁引用我，语义还成立吗）+ 出链（我引用的对象还可达吗）。
3. **新增 = 声明去向**：新节点必须带至少一条出链指向内容层，禁止"无来源无去向"的孤岛节点。
4. **整理后必检**：跑一致性扫描（引用路径真实存在、同一事实多源表述一致、技能名/文件名引用可解析）。
5. **一视同仁**：内置记忆 / fact_store / 技能 / AGENTS.md / 项目文档同等适用。

## 分层落地模式（大型项目标配）

```
L1 索引层（每轮/每次可见，简短）  = 指针条目：一句话"内容在哪"
   ↓ 指向
L2 内容层（按需激活）             = 事实库（结构化）/ 技能（程序性知识）/ 文档（状态决策）/ 会话历史（无限兜底）
```

- **激活链三层**：① 触发 = 技能 description 语义匹配（触发词要覆盖项目定稿名/别名/参与者常用称呼）② 流程 = 项目 AGENTS.md 强制"会话开启流程" ③ 内容 = fact/技能/文档
- **死点防呆**：在索引层与流程层写死"**索引层为空 ≠ 信息不存在**，先按激活链取数"——这是外挂记忆唯一可能翻车的点
- **无人工会话（定时任务）**：无 AGENTS.md 注入 → 必须配 `workdir=项目目录`，或 prompt 里写绝对路径

## 操作清单（每次改动走一遍）

- [ ] 删除前：grep 全库引用 → 重定向或同步删
- [ ] 修改后：入链验证 + 出链验证
- [ ] 新增时：写出链目标（指向哪个 fact/技能/文档）
- [ ] 整理后：`scripts/scan_links.py` 跑路径存在性 + 关键事实 3-5 处多源交叉核对
- [ ] 大重组后：死点模拟测试（delegate 子代理跑冷启动场景，见下）

## 死点模拟测试法（验证激活链）

delegate_task 派 2-3 个子代理模拟"全新会话开局"（子代理=全新上下文+独立终端，最接近真实冷启动）：
- 场景 A：**非触发词提问**（用户用项目定稿名/别名，不在任何技能触发词里）
- 场景 B：**任务型提问**（验收/查询类，测对位技能触发）
- 场景 C：**无人值守任务**（测 prompt 自包含 + 路径解析）
每个子代理要求报告：识别依据 / 加载了哪些技能 / fact probe 结果 / 死点与修复建议。

## 实战实例（匿名化）

- **外挂改造**：内置记忆水位从高位（90%+）降到 60% 上下，条目数减半，项目事实全部外挂 fact_store + 技能 + AGENTS.md
- **悬空指针修复**：删掉桌面上的阶段性打包产物后，某技能 4 处引用指向已删文件 → 一致性扫描揪出并修复（链表第一律的教科书案例）
- **死点测试**：3 子代理模拟 → 抓出无人值守任务 workdir 缺失（路径解析失败）、触发词过窄、项目实体未建（probe 落空）等 5 死点，逐一修复
- **多源一致性**：采购清单 / 数据集路径 / 某宣称数字 / 时间记录 四处关键事实在 memory/fact/技能/文档表述一致

## 大整理执行模板（整理+清理+更新+打包类任务）

标准流程（用户批准后执行）：

1. **先盘点后映射**：派 4 个只读审计子代理并行（各分一个目录区），每区产出逐文件处置清单（A更新/B合并/C归档/E不动），写盘 `_system/_audit/`
2. **处置四档**：A=更新内容（按 SSOT 口径表改）、B=合并精简、C=归档只移不删、E=不动（保护清单/历史记录）
3. **保护清单先行**：确认提交基线/SSOT/证据包一字不动；"以为在保护清单实际不是"要揪出（如 v3 非 v3.1、已作废同名件）
4. **历史记录不动铁律**：任务卡/交付区/简报/角色卡/知识库=日志类，含旧口径字样也不改；只改仍在生效的指南/手册/总览
5. **口径统一替换表**：从 SSOT 文档抽取一张替换表（旧值 → 新口径），**所有子代理共用同一张表**
6. **打包排除清单**：大目录（模型二进制/模板库/数据资产/归档区/临时产物）明确排除；数据资产用清单替代实体；`.env` 密钥类单独隔离禁入包
7. **执行后验证**：口径残留复核（合法语境词过滤：弃用/禁/官方标称/教训）、保护文件在包内抽查、已归档物不入包检查、CHANGELOG 补录
8. **遗漏发现**：镜像文档仍是旧口径副本 → 推送前须核验；`webapp/.env` 含真实密钥 → 隔离 + 建议吊销

## 坑位

- **"删了东西没查引用"是悬空指针第一来源**（文件删除 > 条目删除）——删除动作和引用检查必须捆绑
- **patch 替换小节标题行 = 易吃掉结构标题**：在多小节文档（CHANGELOG/总览类）"某标题行前插入新小节"时，若 old_string 只匹配原标题、new_string 忘记包含它，原标题被替换掉 → 小节标题丢失、其表格成悬空表。正确做法：new_string 末尾追回原标题；改完立刻 `grep -c '^## '` 核对小节数与改前一致
- **CRLF 文件多行 patch 常匹配失败**（报 Could not find match + whitespace difference）：改用 python 行级/字节级插入（读全文→检测 `\r\n`→按原换行符拼接→替换→写回），比反复重试 patch 快
- 路径引用注意反斜杠转义（patch 写 `\r` `\b` 会被当转义写坏文件）——改路径用正斜杠或 python 字节操作
- 技能 description 触发词要覆盖**项目定稿名/别名/参与者常用称呼**（用户常用但原触发词没有的词）
- probe 实体可能落空（实体未建）→ 指引写"probe 或 search"双保险
- 扫描脚本的误报要人工判断（描述性路径 vs 真实引用）
- **改知识节点的场景识别要前置**：任何 memory 条目/文档/技能修改前先问"这是不是知识节点"——是就挂本技能，哪怕只是等长替换（失联复盘：把改 memory 条目当普通 replace 硬塞，忘了挂链）
- **memory 写满 ≠ 放弃更新**：满水位的正确降级路径 = **内容层先落（语义库/文档）→ 回来 L1 指针等长替换**，而不是"暂缓"。等长替换在满水位下可行（实测可写入）——但仅适用于**字数不变或微变**的更新；需要净增字数的大改动必须走完整整理腾出空间
- **"不依赖内置记忆"是错误表述**：L2 外挂的前提恰恰是 L1 指针在——外挂记忆唯一翻车点就是"索引层为空 ≠ 信息不存在"（死点防呆）。说"外挂了就不用管 memory"会自断激活链

## 借鉴参考（不造轮子的出处）

| 来源 | 思路 | 借鉴点 |
|---|---|---|
| **claude-mem**（thedotmack/claude-mem，跨会话记忆） | 3 层渐进披露：`search` 紧凑索引（~50-100 token/条）→ `timeline` 选中项上下文 → `get_observations` 仅对过滤 ID 拉全文（~500-1000 token/条） | **渐进披露**：索引层要极简，详情按需取——对应本技能 L1 只放指针、L2 按需加载；fact_store probe/search 也是"先摘要后取数" |
| **Zettelkasten 卡片盒法**（方法论鼻祖） | 原子卡片 + 双向链接 | **双向链接**：本技能指针目前单向"详见"，入链检查（谁引用我）即反向索引，应常态化 |
| **broken-link-checker / LinkChecker**（URL 版体检） | 分级报告 broken/junk/excluded；可挂 CI/CD 自动检查 | **分级报告**：scan_links 输出分"真悬空 / 规划性引用 / 描述性误报"三类，避免一锅端 |
| **awesome-claude-skills 生态** | 记忆类技能百花齐放（mem-search、memory OS 等） | 生态位分化：本技能专注"大型项目知识链维护"，与记忆存储类方案互补 |

**结论**：本技能的链表五律 + 分层激活与主流方案（渐进披露/双向链接/完整性体检）同构且不重复造轮子——差异点在于**面向大型项目多载体（记忆/fact/技能/文档）的统一链维护**，这是现有方案没有覆盖的。

## 支持文件

- `scripts/scan_links.py`：扫描目录内文档/脚本中的路径与技能名引用，报告悬空（不存在）引用——链表完整性自动化体检（`--help` 看环境变量与用法）
- `references/classification_rules.md`：信息类型 → 唯一载体 归属表（根治重复的分类法则）
